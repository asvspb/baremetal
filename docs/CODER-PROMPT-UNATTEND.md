чек-листе спеки тем же коммитом, что и решение.

## Окружение

- Работа на Linux (bash). PowerShell на этой машине НЕТ. Права root
  не запрашивай: правки статические, тесты через `make test-fast`
  (loop-тесты автоматически уйдут в SKIP, если loop недоступен).
- Реальная Windows-машина недоступна: поведение FirstLogonCommands на железе
  проверяется владельцем вручную по чек-листу TEST-SPEC §11 — твоя зона:
  well-formed XML + автотесты.

## Железные правила (нарушение = переделка)

1. Один коммит = одна задача. Формат сообщения: `W1: first-logon telemetry+ads
   in unattend template`.
2. Новых плейсхолдеров `__X__` в шаблон НЕ добавлять (мета-тест M-2 должен
   оставаться зелёным без правок).
3. `FirstLogonCommands` живёт ВНУТРИ существующего компонента
   `Microsoft-Windows-Shell-Setup` pass `oobeSystem` (после `</AutoLogon>`);
   второй компонент с тем же именем в том же проходе невалиден.
4. Нумерация `<Order>` фиксирована спекой: W1 → 1–5, W2 → 6, W4 → 7 —
   между задачами не перенумеровывать.
5. В командных строках XML не использовать символы `<`, `>`, `&` — они
   ломают разбор шаблона.
6. Не выходить за рамки задачи: никакого рефакторинга соседнего кода,
   переименований, перевода сообщений, изменения UX.
7. Поведение `--dry-run` всех режимов остаётся рабочим.

## Проверки после каждой правки

```bash
xmllint --noout templates/unattend.xml.template   # well-formed
bash -n deploy.sh
shellcheck -S warning deploy.sh                   # только комментированные disable
bash -n deploy.conf                               # после W3
make test-fast                                    # весь корпус зелёный
```

После W1/W2/W5/W6 — убедиться, что новые тесты M-3/U-D8/U-D9 зарегистрированы
в `docs/TEST-SPEC.md` (таблица §5) и входят в `make test-fast`.
