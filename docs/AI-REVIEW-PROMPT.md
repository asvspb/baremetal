## Проект: deploy-baremetal

Набор автономных скриптов для подготовки рабочих станций «с нуля».

### 1. Мастера создания загрузочной флешки Ventoy

`make-boot-usb.sh` (Linux, bash, запуск под sudo) и `make-boot-usb.ps1`
(Windows, Windows PowerShell 5.1, запуск от администратора) — два
взаимодублирующих интерактивных мастера:

- Разметка GPT с UEFI Secure Boot: раздел 1 — exFAT 8/16 ГБ (метка FD-0/FD-1/…,
  тема Ventoy Xenlism-Ubuntu 1080p, `ventoy.json`, сюда пользователь ВРУЧНУЮ
  кладёт ISO-образы); раздел 2 — FAT16 32 МБ `VTOYEFI` (скрытый загрузчик);
  раздел 3 — остаток диска под данные (F2FS со сжатием / exFAT / NTFS) с
  копией автономного пакета deploy-baremetal.
- Выбор флешки с защитой системных дисков; размер раздела 1 спрашивается в
  начале мастера (8/16/кастом/весь диск).
- При переразметке существующей флешки: бэкап данных и ISO в каталог на диске,
  сверка скопированного дерева, восстановление; бэкап удаляется только после
  успешной верификации.
- Скрипты сами скачивают только Ventoy и тему. В `.sh` есть функция
  `download_with_progress`: тихий `wget -c` в фоне + однострочная шкала
  прогресса (`[####----] % / КБ/с / ETA`), 5 ретраев, размер из Content-Length.
  В `.ps1` скачивание через `Invoke-WebRequest -UseBasicParsing` — без
  докачки и с нативным (медленным) прогресс-баром PS 5.1.
- После записи — замеры скорости чтения/записи разделов.
- Жёсткие требования кодировок: `.ps1` — UTF-8 with BOM + CRLF (русские
  сообщения под PS 5.1), `.bat` — CP866; запрещены «умные» кавычки и
  `$имя:` внутри двойных строк; статический контроль — `check-files.sh`
  в pre-commit hook.

### 2. Установщик Dual-Boot

`deploy.sh` (запускается позже, локально или с флешки) — интерактивный
установщик Ubuntu 24.04 + Windows 11/10 Pro:

- Режим `--prep-disk`: GPT-разметка (EFI 500 МБ, MSR 16 МБ, Windows C: 250 ГБ,
  Recovery 1 ГБ, Shared D: 100 ГБ exFAT, Ubuntu `/` 150 ГБ, swapfile 4 ГБ,
  `/home` — остаток; размеры в `deploy.conf`) и генерация полного
  `autounattend.xml` из `templates/unattend.xml.template` (файл кладётся рядом
  с Windows ISO на флешке).
- Windows ставится штатным установщиком, загруженным из ISO через меню Ventoy
  (прежний способ распаковки через `wimlib-imagex` удалён — не создавал
  загрузчик). Ubuntu ставится последней (`--reinstall-ubuntu`), GRUB +
  os-prober строят меню Dual-Boot.
- ISO-образы ищутся по маскам имён (`*win*.iso` / `*windows*.iso`,
  `*ubuntu*.iso` / `*noble*` / `*jammy*`) в каталоге скрипта, `/isodevice`,
  `/cdrom`, `/media`, `/mnt`, `/tmp`, `$HOME` — то есть официально
  скачанные образы подхватятся автоматически, связывать ничего не нужно.

### 3. Вспомогательное

`split-home.sh` — безрисковое разделение существующей Ubuntu на `/` и `/home`.

### 4. Тесты

6 уровней: L0 (статика) → L1 (парсинг `.ps1` через pwsh) → L2 (юниты, bats) →
L3 (интеграция на стабах и фейковых `/dev/fakedisk*`) → L4 (реальные
parted/mkfs только на `/dev/loop*`) → L5 (dry-run E2E против golden).
`make test-fast` (L0–L3) идёт без root и подключён в pre-commit. Тесты никогда
не пишут на реальные диски; заглушка `dd` всегда возвращает ошибку.

### 5. Ограничения среды

Аудитория — машины в России (локаль ru_RU, TZ Europe/Moscow):
`releases.ubuntu.com` бывает медленным; страница
microsoft.com/software-download и Media Creation Tool из РФ недоступны,
но серверы доставки обновлений MS (`tlu.dl.delivery.mp.microsoft.com`,
`fg.download.windowsupdate.com`) доступны. PowerShell-код обязан работать под
Windows PowerShell 5.1 (не pwsh 7).

## Обсуждаемая фича

Добавить в оба мастера (`make-boot-usb.sh` и `.ps1`) меню «выбрать и скачать
дистрибутивы»:

- **Ubuntu 24.04 LTS / 22.04 LTS**: официальные URL `releases.ubuntu.com` +
  проверка по `SHA256SUMS`; приоритет быстрого зеркала (например,
  `mirror.yandex.ru/ubuntu-releases/`) с фолбэком на официальный сервер.
- **Windows 11 / Windows 10**: подход Fido (как в Rufus) — запрос у Microsoft
  временной (~24 ч) прямой ссылки на ISO нужного языка/редакции/архитектуры
  через неофициальный API; опубликованных SHA256 нет, целостность = HTTPS с
  серверов MS. Фолбэк — запрос пути к локально скачанному ISO.
- Пункты «свой URL» и «указать путь к локальному файлу».
- **UX разметки**: вопрос «что будет на флешке» перенести ДО выбора размера
  раздела 1 и рекомендовать размер автоматически (Ubuntu 24.04 ≈ 6 ГБ +
  Windows 11 ≈ 6.3 ГБ → нужно ~13 ГБ).
- В `.sh` переиспользовать `download_with_progress`; в `.ps1` кандидат —
  `Start-BitsTransfer` (нативный прогресс + resume, есть в Win10/11 Pro)
  вместо `Invoke-WebRequest`.

## Что оценить (4 блока)

1. **Архитектура проекта**: дублирование логики bash↔PowerShell (оба мастера
   написаны дважды), обработка ошибок, защита данных пользователя,
   тестируемость, поддерживаемость. Назови 3–5 главных архитектурных рисков,
   каждый — со ссылкой на конкретные факты из описания, без общих слов.
2. **Фича скачивания**: feasibility и риски. Отдельно разбери: легитимность и
   живучесть Fido-подхода (неофициальный API MS, прецедент Rufus),
   альтернативы (автоматизация MCT, только ручная загрузка + ввод пути,
   плагины Ventoy), докачка после обрыва на 6-гигабайтном файле, нехватка
   места на разделе или диске, действия при расхождении SHA256.
3. **Встраивание**: порядок вопросов в мастере, точки интеграции (до
   разметки? после монтирования разделов?), влияние на существующий поток
   бэкап → переразметка → восстановление, как тестировать в системе L0–L5 без
   реальной сети.
4. **Альтернативы всей затее**: возможно, задача решается лучше без
   встраивания скачивания в мастера.

## Формат ответа (строго; ответы нескольких моделей будут сравниваться)

1. **Вердикт** — одной строкой: фича «можно / можно с оговорками / не стоит»

3. **Оценка фичи** — отдельно: Ubuntu / Windows (Fido) / планирование места /

4. **Рекомендации** — порядок шагов, точки интеграции, тестирование.
5. **Альтернативы**, которые мы не рассмотрели.
6. **Уверенность** в каждом блоке: низкая / средняя / высокая.

проекта («добавить тестов», «улучшить документацию») не засчитываются; если
считаешь фичу ненужной или знаешь существенно лучшее решение — скажи прямо и
обоснуй. Отвечай на русском.
